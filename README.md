# swift-clock-interposed

Use this package when a test must control time in code that reads the machine's clock directly, not through a clock it is handed: Core Animation's media time, a run loop's timers, a framework that calls `mach_absolute_time`. `Clock.Interposed`, nested in swift-clock's `Clock`, is the process's own uptime as every image of the process reads it, which a test freezes and then moves on by exactly the time it chooses, however long the wall clock runs. It is also a clock of Swift's own (`Clock.Nonsending` of swift-clock), so code that takes a clock and sleeps keeps step with the same time. The executable that uses it has the `Clock Interposed Interposition` library in it from launch; the clock needs a process of its own, since every thread and framework in it reads the same frozen time. Where the code under test takes a clock as a value and nothing else in the process must keep step, swift-clock's `Clock.Test` needs no library and no process of its own.

## Laws

- The `Clock Interposed Interposition` library replaces four ways of reading the machine's uptime for every other image of the process: `mach_absolute_time`, `mach_continuous_time`, `mach_approximate_time` and, where QuartzCore is, `CACurrentMediaTime`. Until the clock is frozen they pass straight through. `freeze()` freezes all four at that instant; from then on they move only by `advance`, by exactly the time advanced. Freezing a frozen clock does nothing, and nothing thaws it: it stays frozen until the process ends.
- The library is a dynamic library because the mechanism needs one: the dynamic linker binds every other image's calls to the replacements only for a library that is in the process at launch, and never replaces calls inside the image that holds the replacements, so the code built into the executable itself would not be replaced. Link the `Clock Interposed Interposition` product into the executable, or start the executable with `DYLD_INSERT_LIBRARIES` naming the built library, which the system ignores for hardened and system binaries.
- `Clock.Interposed()` fails with `.absent` without the library in the process and with `.unhooked` with a library loaded after launch, whose replacements are not bound; in both cases nothing is frozen. It learns which by asking the library to answer the calling thread's next `mach_absolute_time` with `UInt64.max` and reading it from its own image. Every `Clock.Interposed` is a handle on the one clock of the process.
- The replacements run from the first read of uptime in the process, before the Swift runtime has initialized anything and before any thread has thread-local storage. So the library is Swift that calls nothing of the runtime: its state is global integers with literal initializers, which the dynamic linker places initialized in the image's data, read and written atomically through their addresses and exempt from exclusivity checks, and its interposition table is a constant in the `__DATA,__interpose` section. No C is needed.
- The clock counts whole nanoseconds from the freeze and never runs backwards. `elapsed` is the time advanced since the freeze, and `now` is `Instant.origin` advanced by it; before the freeze both stand at zero. `advance(to:)` and `advance(by:)` cut to whole nanoseconds, and refuse an instant before `now` with `.backwards`, one past what 64 bits of nanoseconds count with `.beyond`, and any advance before the freeze with `.running`, moving nothing.
- What the clock does not reach: the wall clock (`gettimeofday`, `CLOCK_REALTIME`), `CLOCK_MONOTONIC`, and other processes. Waits follow from which clock they read. A run-loop timer set while the clock is frozen fires only once the clock has been advanced past its fire time. A dispatch deadline and `Task.sleep` on the system's clocks are waited out by the kernel in real time; a sleep on `Clock.Interposed` is not. Measured on macOS 27.2 on Apple silicon; no other platform was tried.
- `sleep(until:tolerance:)` returns at once, without suspending, for a deadline the clock has reached; otherwise it suspends, holding no thread, until an advance reaches the deadline, never by the wall clock. A sleep begun before the freeze is measured from `Instant.origin`. The sleeps an advance reaches are resumed one after another, earliest deadline first and, among equal ones, in the order they began: the advance resumes the first and returns, and each, as it resumes on the actor it slept on, resumes the next, so the sleeps of one actor run in that order, each up to its next suspension before the next begins. A sleeper reads `now` as the instant advanced to. A task cancelled before or while it sleeps throws `CancellationError` at once, the clock unmoved, and a later advance does not resume it. The tolerance is not used.
